# DECISIONS — архитектурные решения и почему так

Короткие ADR-записи. Если меняешь решение — добавь новую запись, не переписывай старую.

---

## ADR-001. Отдельный форк и отдельная инфраструктура

**Решение:** `SceneEngine` — отдельный репозиторий и compose-проект.
Порты `5175 / 8002 / 5436`, БД `scene_db`, том `scene_postgres_data`.

**Почему:** исходный проект продолжает кормить YouTube-канал; форк можно ломать
и перестраивать, не рискуя рабочим пайплайном.

**Следствие:** два проекта можно запускать одновременно.

---

## ADR-002. Сцена = sandboxed iframe + `seek(t)`

**Решение:** сцена — HTML/CSS/JS в iframe (`sandbox="allow-scripts"`), обязана
реализовать `window.scene.seek(t)`.

**Почему:**
- изоляция CSS/JS от редактора;
- сцена хранится как данные, а не как Vue-компонент;
- ИИ может писать сцену целиком;
- один рантайм для плеера и рендера.

**Следствие:** внутри сцены запрещены `rAF`, `Date.now`, `setInterval`,
бесконечные CSS-анимации. Время приходит только снаружи.

---

## ADR-003. GSAP + SceneKit, а не свой движок анимации

**Решение:** в iframe инжектится локальный GSAP и `SceneKit` (cues/integrate/
mechanism/parallax/views).

**Почему:** GSAP — зрелый, умеет paused timeline и `seek`; `SceneKit` даёт
детерминированные ключи и интеграл скорости.

**Следствие:** сцена может использовать GSAP или чистый JS; `SceneKit` не обязателен.

---

## ADR-004. Внутренняя таблица `slides` пока остаётся

**Решение:** сцены хранятся в `slides` с `component='__scene__'` и полями
`kind/duration/code/props/props_schema/track/z_index`.

**Почему:** плеер, аудио-таймлайн, ревизии и рендер уже завязаны на `slides`.
Переименование таблицы — отдельная миграция, чтобы не ломать рабочие механизмы.

**Следствие:** публичный домен — `scenes`, API — `/scenes`, UI — «сцены».
Переименование таблицы запланировано, но не в Phase 1.

---

## ADR-005. Realtime-рендер сохраняется

**Решение:** `render_fullscreen_capture.py` остаётся; добавлен handshake
`window.__sceneReady` перед стартом захвата.

**Почему:** механизм работает и проверен на старом проекте; ломать его нельзя.

**Следствие:** покадровый `engine=frame` — отдельная будущая опция, не замена.

---

## ADR-006. Библиотека = миры + объекты + механизмы, а не UI-компоненты

**Решение:** `scene_library.py` содержит `ENVIRONMENTS`, `OBJECTS`, `TEMPLATES`.
Никаких карточек/дашбордов как шаблонов сцен.

**Почему:** пользователь делает 2D-миры и физические объекты, а не презентационные
UI-блоки. UI-шаблоны были ошибкой первого подхода и удалены.

**Следствие:** новые шаблоны — только композиции мира и объектов.

---

## ADR-007. Классификация совместимости

**Решение:** у мира есть `domain` (outdoor/indoor/stage), у объекта — `domain`,
`environments`, `surface`, `views`.

API:
- `GET /scene-library/environments/{slug}/objects`
- `GET /scene-library/objects?environment=forest`
- `GET /scene-library/compatibility`
- `POST /scene-library/validate-composition`

**Почему:** нельзя ставить небоскрёб в квартиру; ИИ и редактор должны это знать.

**Следствие:** редактор фильтрует объекты по выбранному миру; несовместимые можно
вставить только принудительно (с предупреждением).

---

## ADR-008. Views: time-of-day + per-object, без глобальной 3D-камеры

**Решение:**
- у мира есть `views` (day/sunset/night/...), сцена задаёт `view`;
- у объекта есть `views` (side/front/corner/...), переключаются через
  `SceneKit.views(root, { car: 'front' })` и CSS-классы `.obj-car.view-front`.

**Почему:** «повернуть все объекты камерой» — это 3D-движок и огромная сложность.
Time-of-day + отдельные ракурсы дают 80% эффекта при малых затратах.

**Следствие:** полноценные multi-angle объекты — Phase 4+, не раньше.

---

## ADR-009. Редактор: code-first + Layers из DOM

**Решение:** редактор остаётся code-first (HTML/CSS/JS), но получает вкладку
`Layers`, которая парсит `.obj-*` из `code.html` и позволяет менять
left/bottom/width/height/z-index/transform/view, дублировать и удалять.

**Почему:** не нужен новый формат сцены; объекты уже в HTML. Это быстрый путь
к управлению объектами без полноценного нодового редактора.

**Следствие:** drag-n-drop и resize на канвасе — следующий шаг (Phase 2).
В будущем возможен layer-модель (`environment + layers[]`) как второй режим.

---

## ADR-010. Чистый старт по данным

**Решение:** старые презентации не импортируются; legacy-адаптер не делаем.

**Почему:** пользователь хочет новый формат, а не тащить 100+ слайдов.

**Следствие:** старые 117 Vue-компонентов остаются мёртвым кодом; их можно удалить
в Phase 2. Старые доки — в `docs/legacy/`.

---

## ADR-011. Документация — часть продукта

**Решение:** `SCENES.md`, `STATUS.md`, `ROADMAP_2D.md`, `PROCESSES.md`,
`WORKLOG.md`, `DECISIONS.md`, `ANIMATION.md`, `SERVER.md` — обязательные.
`AGENTS.md` — точка входа для ИИ.

**Почему:** работа должна продолжаться на сервере без автора.

**Следствие:** каждое изменение поведения документируется; ошибки — в WORKLOG.


---

## ADR-012. Human+AI: AI производит, человек утверждает

**Решение:** продукт строится как конвейер с воротами качества:
brief → storyboard → scene draft → animation/cues → QA → render → publish.
Для низкого риска — human-on-the-loop, для сцен/персонажей — human-in-the-loop,
для бренда/фактов — human-in-command.

**Почему:** полностью автономный ИИ даёт нестабильное качество и риск
фактических/брендовых ошибок; человек должен утверждать смысл и финал.

**Следствие:** нужны статусы сцен, review/approve, комментарии, diff, аудит,
AI-предложения с превью. Это Phase B/C роадмапа.

## ADR-013. Обучаемый реестр ошибок

**Решение:** таблица `scene_learnings` + API `/scene-library/learnings`.
ИИ читает правила перед генерацией и добавляет новые после QA/ревью.

**Почему:** ошибки не должны повторяться; процесс должен улучшаться с каждой сценой.

**Следствие:** `AGENTS.md` требует читать learnings; `docs/LEARNINGS.md` —
человекочитаемый обзор.

---

## ADR-014. Полный DAM, а не «папка с файлами»

**Решение:** проектируем `assets/asset_variants/asset_tags/asset_collections/
asset_usages/asset_versions` (`docs/ASSETS.md`).

**Почему:** нужны варианты, права, использования, поиск и защита от удаления
используемого ассета.

**Следствие:** это отдельный слой; `media_files` остаётся для legacy.

---

## ADR-015. Персонажи: video-only, SVG-риг первым

**Решение:** начинаем с SVG-рига и visemes; Rive/Spine/DragonBones —
кандидаты для сложных ригов. Интерактив не нужен.

**Почему:** видео требует детерминированного seek, а не state machine в браузере;
SVG даёт полный контроль и встраивается в текущий iframe.

**Следствие:** `docs/CHARACTERS.md` — сравнение и план; объект `character` —
заготовка, не финальный движок.
