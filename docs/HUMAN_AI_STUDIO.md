# HUMAN_AI_STUDIO — как построить фабрику 2D-контента с контролем человека

> Исследование лучших практик 2026 + адаптация под SceneEngine.
> Цель: ИИ производит сцены, человек управляет смыслом, стилем и качеством.

---

## 1. Главный вывод

Лучшие продукты 2026 года не пытаются «автоматизировать всё». Они строят
**конвейер с воротами качества**:

```
Бриф → План/раскадровка → Черновик сцены → Анимация/ключи → QA → Рендер → Публикация
        ↑ человек       ↑ человек          ↑ человек       ↑ авто+человек ↑ человек
```

ИИ делает объём: варианты, ассеты, код сцен, черновой монтаж, проверки.
Человек принимает решения: что оставить, что переделать, что нельзя менять.

Три режима контроля (HITL):
- **Human-on-the-loop** — ИИ делает сам, человек наблюдает и вмешивается.
  Подходит для черновых ассетов, фонов, вариаций.
- **Human-in-the-loop** — человек утверждает до того, как изменение уйдёт дальше.
  Подходит для сцен, ключевых кадров, анимации, рендера.
- **Human-in-command** — человек решает всё. Подходит для бренда, фактов,
  юридических утверждений, финального ролика.

## 2. Что взять из лучших практик

### HyperFrames (HeyGen)
- **HTML — источник истины.** Агент, Studio, CLI и рендерер работают с одним
  и тем же проектом. Studio правит тот же DOM, который рендерится.
- **Studio редактирует видимые свойства и тайминг, а структурные правки
  возвращает агенту.** Это ровно наш сценарий: человек крутит слайдеры,
  ИИ переписывает сцену.
- **Skills для агентов** — правила и проверки встроены в рабочий процесс.
- **Catalog/registry** — переиспользуемые блоки, переменные, ассеты.
- **Clip-модель:** `data-start`, `data-duration`, `data-track-index`,
  paused timeline. У нас аналог — `SceneKit.cues` + `seek(t)`.

Что берём: HTML-сцена, Studio на том же DOM, каталог миров/объектов,
AI-skills, проверка перед рендером.

### Remotion
- **Кадр = функция от времени.** Детерминизм и параллельный рендер.
- **Типизированные props** — контракт сцены.
- **Timeline-компонент** — слои, дорожки, zoom.
- **Зрелый рендер** — Lambda/Cloud Run.

Что берём: строгий `seek(t)`, типы props, таймлайн, очередь рендера.

### Theatre.js
- Sequence editor: ключи, aggregate keyframes, focus range, tween editor,
  multi-track curve editor, copy/paste, selection.
- Ключи можно ставить на compound props и двигать группой.

Что берём: UI ключей и кривых; не тащить весь движок, а повторить паттерны
в нашем Cues/Keys редакторе.

### Rive / липсинк
- 10 визимов (A/E/I/O/U/M/F/...), state machine с числовым входом `phoneme`.
- Тайминги персонажей из TTS (character-level timestamps) → массив
  `{ chars, viseme, timeMs }`.
- Лёгкий fake-3D параллакс головы оживляет персонажа даже в молчании.

Что берём: viseme-таймлайн, state-machine-подход, rig-части, позже — Rive/Spine
как runtime для сложных персонажей.

### Human-in-the-loop (Velt, Manava, Ortem)
- **Confidence-gated routing:** авто-одобрять уверенное, звать человека на
  рискованном. Не отправлять человеку всё — иначе review fatigue.
- **Review interface:** контекст (что изменилось, почему), а не просто «approve».
- **Audit trail:** кто, что, когда, на каком основании.
- **Approval gates** на опасных действиях.
- **Reviewer context** и понятные статусы.

Что берём: статусы сцен, очередь ревью, комментарии к времени/объекту,
diff, аудит, пороги риска.

### Motion studio pipeline (TapVid)
- ИИ генерирует 20–30 style frames — человек курирует, а не тонет в вариантах.
- Ассеты/фоны/текстуры — ИИ; **консистентность персонажей всё ещё ручная**.
- Появилась роль **AI QA** — искать временные артефакты, несоответствия, off-brand.
- AI-композитинг (ротоскоп, свет, blend modes) — рост эффективности.

Что берём: курируемые варианты, отдельный QA-этап, не ждать от ИИ
консистентности персонажей без рига.

### DAM / ассеты
- Метаданные, теги, варианты, превью, права, поиск.
- Один ассет = много вариантов (формат, цвет, ракурс).

Что берём: библиотека миров/объектов/ассетов с метаданными и вариантами.

## 3. Модель продукта

### Роли
| Роль | Кто | Отвечает |
|---|---|---|
| Showrunner / человек | ты | смысл, стиль, финальное «да» |
| AI Planner | агент | бриф → план, 3–5 вариантов сцен |
| AI Scene Author | агент | HTML/CSS/JS сцены, props, cues |
| AI Asset Librarian | агент | миры, объекты, варианты, теги, превью |
| AI QA | агент | forbidden APIs, детерминизм, overflow, контраст, битые ассеты |
| Human Reviewer | ты/редактор | approve/reject, комментарии, правки |
| Render Operator | агент | очередь рендера, форматы, публикация |

### Ворота качества
1. **G0 Brief** — человек задаёт цель, аудиторию, формат, длительность, тон.
2. **G1 Storyboard** — ИИ даёт 3–5 вариантов; человек выбирает.
3. **G2 Scene draft** — ИИ пишет сцену; человек смотрит превью.
4. **G3 Animation** — ИИ предлагает ключи; человек крутит слайдеры/тайминг.
5. **G4 QA** — авто-проверки + человек.
6. **G5 Render** — человек утверждает финальный mp4.
7. **G6 Publish** — человек/publication.

Для низкого риска (фон, декор) — human-on-the-loop.
Для сцен/персонажей/финала — human-in-the-loop.
Для бренда/фактов/юридики — human-in-command.

## 4. Интерфейс

```
┌──────────────────────────────────────────────────────────────────────┐
│ Project / Scene / Status (draft → review → approved)   [AI] [Render] │
├──────────────┬───────────────────────────────────────┬───────────────┤
│ Scenes       │                                       │ Inspector     │
│ Worlds       │          PREVIEW 16:9 / 9:16          │ Layer         │
│ Objects      │      selection, drag, safe-zone        │ Cues / Keys   │
│ Assets       │                                       │ Props         │
│ Renders      │                                       │ Code          │
│              │                                       │ AI            │
├──────────────┴───────────────────────────────────────┴───────────────┤
│ TIMELINE: world | objects | characters | audio | captions | events   │
│ playhead · cues · keyframes · zoom · snap                            │
└──────────────────────────────────────────────────────────────────────┘
```

### Левая панель
- **Scenes** — список сцен, статус, длительность.
- **Worlds** — миры (forest/city/...), совместимость.
- **Objects** — объекты, отфильтрованные по миру.
- **Assets** — медиа, шрифты, звуки, варианты.
- **Renders** — очередь и история.

### Центр
- Превью в выбранном формате.
- Выделение объектов, drag, resize, snap, alignment.
- Safe-zone, сетка, направляющие.
- Compare mode: текущая vs предыдущая версия.
- Play/pause, scrub, frame step.

### Правая панель
- **Layer** — слайдеры: X/Y, ширина/высота, масштаб, поворот, opacity, z-index.
- **Cues** — ключи на локальном таймлайне: время, параметры.
- **Props** — параметры сцены (авто-форма из `props_schema`).
- **Code** — HTML/CSS/JS с подсветкой и ошибками.
- **AI** — чат/команды с контекстом сцены.

### Таймлайн
- Дорожки: мир, объекты, персонажи, аудио, субтитры, события.
- Ключи/механизмы: `{ at, set }`.
- Focus range (Theatre-style), tween/easing, copy/paste.
- Привязка к фактическим акцентам аудио.

### Review mode
- Комментарии, привязанные к времени и объекту.
- Approve / Request changes / Reject.
- Diff: что изменилось в коде/сцене/тайминге.
- История версий и откат.
- Статус: draft → review → approved → locked.

## 5. AI-взаимодействие

### Команды
- «Собери сцену по этому сценарию».
- «Сделай лесную трассу, машина едет, колёса крутятся».
- «Добавь ключ: на 2.2 с ускорить, на 4.6 с затормозить».
- «Переделай под 9:16».
- «Проверь детерминизм и переполнение».
- «Сделай 3 варианта начала».

### Контекст для ИИ
- бриф проекта;
- стиль/токены;
- текущая сцена (код, props, cues, layers);
- совместимые миры/объекты;
- аудио-таймлайн и транскрипт;
- история ревизий и комментарии;
- правила `ANIMATION.md` и `AGENTS.md`.

### Формат ответа
ИИ возвращает **предложение**:
```json
{
  "summary": "Машина едет по лесу, на 2.2с ускоряется, на 4.6с тормозит",
  "scene": { "code": {...}, "props": {...}, "cues": [...] },
  "warnings": [],
  "preview_frame": "data:image/..."
}
```
Человек видит diff/превью и нажимает Approve.

### Защита
- sandbox + forbidden APIs;
- детерминизм (двойной seek → одинаковый кадр);
- overflow/contrast/asset checks;
- brand/claims lock: ИИ не может менять запрещённые поля;
- audit trail.

## 6. Что уже есть в SceneEngine

- `SceneHost` + `seek(t)` + handshake.
- `SceneKit`: cues/integrate/mechanism/parallax/views.
- 5 миров, 16 объектов, 5 шаблонов.
- Классификация совместимости.
- Views: time-of-day + per-object.
- Редактор: Layers (слайдеры), Cues (ключи), Props, Code.
- API сцен и библиотеки.
- Realtime-рендер + заготовка frame-step.
- Ревизии/аудио/медиа.

## 7. Чего не хватает

1. Drag/resize на канвасе, snap, multi-select.
2. Keyframe-редактор как в Theatre.js (кривые, aggregate, focus range).
3. Thumbnails и превью миров/объектов.
4. Asset library с метаданными/вариантами.
5. Статусы сцен и review/approval.
6. Комментарии к времени/объекту.
7. Diff версий и откат.
8. AI-предложения с превью и approve.
9. AI QA и валидатор сцены.
10. Очередь рендера и публикация.
11. Персонажи: риг, idle/walk/talk, visemes, lipsync.
12. Мульти-формат: 16:9 / 9:16 / 1:1 с проверкой.

---

## 8. Что не делать

- Не строить полностью автономного ИИ без ворот качества.
- Не делать нодовый редактор раньше слоёв/таймлайна.
- Не ждать от ИИ консистентности персонажей без рига.
- Не давать 100 вариантов без курирования — это review fatigue.
- Не тащить 3D-камеру в 2D-движок.
- Не заменять код сцены «умным» JSON-конструктором, пока код даёт гибкость.

## 8.5. Object Studio и ворота

- **Object Studio:** создание объекта по промпту/фото прямо в редакторе
  (`OBJECT_STUDIO.md`). Фото → sprite/cutout/vector/ref; не риг.
- **Ворота:** storyboard + scene обязательны. Отдельный approve на
  animation/cues — опционально; по умолчанию человек может точечно править.
- **Learnings:** ИИ добавляет `proposed`, человек утверждает в `active`.

## 11. Решения пользователя (2026-10-22)

1. **Утверждение:** и раскадровка, и каждая сцена. Процесс обучаемый: все
   найденные ошибки ИИ документирует в `scene_learnings` (`docs/LEARNINGS.md`),
   чтобы не повторять.
2. **Режим ИИ:** и прямое редактирование, и diff-предложения. Сначала работа
   идёт в интерфейсе opencode, поэтому нужна качественная документация всего
   движка (`ENGINE.md`, `API.md`, `EDITOR.md`, `SCENES.md`, `PROCESSES.md`).
   Позже — агенты по API прямо в проект.
3. **Персонажи:** рассматриваем Rive/Spine и бесплатные аналоги
   (`docs/CHARACTERS.md` §7). Пока — SVG-риг-заготовка.
4. **Персонажи только для видео**, без интерактива в браузере.
5. **Ассеты:** полный DAM-пакет (`docs/ASSETS.md`): метаданные, варианты,
   теги, коллекции, использования, права, версии.
6. **UI:** развиваем итеративно, правим по ходу.

### Что это меняет в реализации

- Ворота: **G1 storyboard** и **G2 scene** обязательны; без approve сцена не
  уходит в рендер.
- Каждая ошибка → запись в `scene_learnings` + правило в `LEARNINGS.md`.
- AI-предложения хранят diff и rationale; прямое редактирование — с audit trail.
- DAM — отдельный слой, не «папка с файлами».
- Персонажи — video-only, значит можно использовать pre-rendered/Rive/Spine
  без интерактивного runtime, но с детерминированным seek.
