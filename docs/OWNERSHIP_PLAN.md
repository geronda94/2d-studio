## 0. Целевая модель владения

| Тип | Признак | Видит | Правит |
|---|---|---|---|
| Системный шаблон (библиотека) | `is_template=true, owner_id=NULL` | все | только админ |
| Личная фирменная тема | `owner_id=U, is_template=false` | только U | только U |
| Проект пользователя | `owner_id=U` | только U | только U |

- «Доработать базовую под себя» = **форк** (`parent_id` на источник), исходник не трогаем.
- «Своя тема» = проект-палитра с `owner_id=U`.
- Пока авторизации нет — резолвер владельца-заглушка (`X-Owner-Id` header; пусто = system,
  видны system-проекты + шаблоны). Когда появится логин — подставить реального юзера, схему не менять.

## 1. Фундамент: схема (S)

- `projects.owner_id` (Integer, nullable, index): NULL = системный.
- `projects.parent_id` (Integer, nullable): происхождение форка (lineage).
- Миграции `ADD COLUMN IF NOT EXISTS` в `seed_templates.py`.
- Приёмка: колонки есть, существующие проекты owner=NULL (поведение не меняется).

## 2. Фундамент: доступ (M)

- `_current_owner(x_owner_id: Optional[int] = Header(None))` → int | None.
- Видимость: `is_template OR owner_id == current OR (owner_id IS NULL AND current IS NULL)`.
  Применить к: `GET /projects/`, `GET /projects/{slug}`, `PUT/DELETE /projects/{id}`,
  и к палитрам/токенам (403 при чужом).
- Приёмка: system видит всё как раньше; чужой owner не видит проекты другого; шаблоны видны всем.

## 3. Фундамент: операции (M)

- `POST /projects/{id}/fork {title?}` — копия проекта как личная тема: `owner_id=current`,
  `parent_id=source.id`, `is_template=false`, токены копируются (replace-семантика, кастомы автора).
- `GET /projects/palettes` — витрина для кабинета: шаблоны + личные палитры текущего.
- `POST /projects/` — уже из шаблона; при создании ставить `owner_id=current`.
- Приёмка: форк создаёт личную копию, шаблон неизменен; палитры фильтруются по владельцу.

## 4. Фундамент: UI (M)

- `HomeView`: секции «Библиотека» (шаблоны, общие) и «Мои проекты» (фильтр по владельцу).
- Кабинет стилей, ось «Тема»: селект из `GET /projects/palettes` (шаблоны + мои),
  кнопка «Форкнуть как свою» рядом с выбранным системным шаблоном.
- `api`: `fetchPalettes`, `forkProject`, проброс `X-Owner-Id` (dev-идентичность из localStorage).

## 5. Совместимость и как не сломать

- owner по умолчанию NULL → текущее поведение идентично (все проекты видны).
- Никаких DROP/переименований; только новые nullable-колонки/эндпоинты.
- `is_template` остаётся признаком витрины; удаление шаблона запрещено (есть).
- P0-конвенция сидов сохраняется.
