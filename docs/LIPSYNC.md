# LIPSYNC — липсинк ведущего и персонажей

Короткий ответ: **настоящий липсинк — это риг + виземы**, а не «анимировать
рот на статичной картинке». Статичный портрет можно оживить костылём
(кадры рта), но качество будет ниже, чем у Rive/DragonBones.

---

## 1. Что нужно для липсинка

1. **Аудио/текст с таймингами** — когда какое слово/звук звучит.
2. **Виземы** — 10 форм рта:
   `0 neutral, 1 AEI, 2 BMP, 3 FV, 4 CDGKNRSTXYZ, 5 U, 6 ChJSh, 7 L, 8 O, 9 QW`.
3. **Риг** — голова/челюсть/рот, которые умеют переключать эти формы.
4. **Драйвер** — на `seek(t)` выбрать визем и применить.

---

## 2. Пайплайн (рекомендуемый)

```
TTS / запись
  → word/char timestamps (Whisper / ElevenLabs / TTS API)
  → scripts/text_to_visemes.py
  → [{ t: 0, viseme: 2 }, { t: 120, viseme: 1 }, ...]
  → scene payload: "visemes": [...]
  → Rive state machine input "phoneme" (или DragonBones viseme frames)
```

### text_to_visemes.py
Вход:
```json
[{"word":"привет","start":0,"end":600}]
```
Выход:
```json
[{"t":0,"viseme":2},{"t":100,"viseme":4},{"t":200,"viseme":1}]
```
Это приближение по буквам; для качества нужны фонемы/тайминги TTS.

### SceneKit
```js
const lip = SceneKit.lipsync({
  visemes: window.__sceneProps.visemes || [],
  onViseme(v) { riveInput.value = v; },
});
window.scene = { seek(t) { lip.seek(t); } };
```
Для статичного портрета `onViseme` может переключать кадр рта.

---

## 3. Варианты реализации

### A. Rive (рекомендуется)
- В Rive: 10 состояний рта + state machine с числовым входом `phoneme`.
- В сцене: `new rive.Rive({ src, stateMachines, autoplay:false })`,
  `stateMachineInputs('...')`, на `seek(t)` выставлять `phoneme`.
- Плюсы: плавные переходы, качественный рот, глаза/брови.
- Минусы: нужен `.riv`-ассет и Rive-редактор; проверить детерминированный seek.

### B. DragonBones (бесплатно)
- 10 кадров/анимаций рта, переключение по визему.
- Плюсы: бесплатно, skeletal.
- Минусы: старее, больше ручной работы.

### C. Статичный портрет + кадры рта (быстрый костыль)
- Сгенерировать 5–10 вариантов портрета с разной формой рта.
- Выровнять по лицу (face landmarks) и накладывать область рта по визему.
- Плюсы: без рига, быстро.
- Минусы: артефакты, дрожание, нечестная мимика; для длинного видео — заметно.

### D. Wav2Lip / talking-head модель
- Нейросеть «натягивает» рот на видео/портрет по аудио.
- Плюсы: реалистично для фото.
- Минусы: тяжело, артефакты на стилизации, лицензии, не детерминировано покадрово.

**Вывод:** для канала — **Rive** (ведущий/соведущая) или **DragonBones**
(бесплатный путь). Костыль C — только для теста.

---

## 4. Текущий статус в проекте

- `SceneKit.visemeAt` и `SceneKit.lipsync` — готовы.
- `scripts/text_to_visemes.py` — приближённый русский текст → виземы.
- Портреты ведущего/каста — детализированные, но **статичные** (дыхание/качание).
- Rive/DragonBones ещё не подключены; `.riv`/skeleton-ассетов нет.
- В сцене можно хранить `visemes` в payload и передавать в Rive-адаптер.

## 5. Что сделать, чтобы получить липсинк ведущего

1. Выбрать Rive (рекомендуется).
2. Сделать/заказать риг ведущего: голова, челюсть, 10 форм рта.
3. Экспортировать `.riv` в `core/public/characters/`.
4. Добавить Rive-адаптер в сцену (`SceneKit.character`/`rive`).
5. TTS → тайминги → `text_to_visemes.py` → `visemes` в payload.
6. Проверить `seek(t)` на 3–4 репликах, 16:9 и 9:16.
7. Для массовки/экспертов — тот же пайплайн или статичные портреты.

## 6. Критерии приёмки

- Рот совпадает с речью на 3–4 тестовых фразах.
- Нет «резинового» лица и дрожания.
- Работает при seek назад/вперёд (детерминизм).
- 16:9 и 9:16.
- Нет артефактов на стыках виземов.
