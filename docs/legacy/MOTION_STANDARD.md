# MOTION_STANDARD — единый стандарт анимации компонентов

Статус: **план на будущее** (не внедрён). Цель — одинаковое «ощущение» движения во всей
библиотеке, управляемое темой/вариантом, при сохранении смысловой разницы между типами данных.

> Это **не** «все анимации одинаковые». Это общий контракт + набор разрешённых приёмов,
> где каждый архетип использует уместный паттерн.

---

## 1. Проблема сейчас

- Каждый компонент сам пишет `ease(clamp01((relativeTime - start) / dur))` → дублирование,
  дрейф кривых и таймингов между файлами.
- Тайминг частично в `useVariant().motion`, но константы (длительности прорисовки линий,
  задержки серий) местами захардкожены в компонентах.
- Разное «богатство» хореографии: где-то fade+slide, где-то scale, единого словаря нет.

## 2. Инварианты (нарушение = баг)

1. Время — **только** из `inject('relativeTime')` (локальное время слайда, мс).
   Никогда `performance.now()`, `Date.now()`, wall-clock.
2. Анимируются **только** `transform` и `opacity` (compositor thread, zero-paint).
   `width/height/left/top/background-position` — запрещены (перерисовка каждый кадр).
   Вместо `width: 0→100%` — `transform: scaleX()`; вместо `background-position` — overlay `translateX`.
3. **Запрещено**: `requestAnimationFrame`, CSS/SVG `infinite`, теги `<animate>`/`<animateMotion>`.
4. Зацикленные эффекты — только математика в шаблоне (`Math.sin(relativeTime/period * 2π)`).
5. Появление — по `relativeTime >= item.start_time` (или `i * stagger_ms` как fallback).
6. Один и тот же кадр при seek и при realtime-захвате (детерминизм).

## 3. Тайминг-токены (единственный источник ритма)

Из `style_variants.config.motion` (через `useVariant().motion`):

| Токен | Смысл | Дефолт (tech) | Пример |
|-------|-------|---------------|--------|
| `appear_ms` | появление одного элемента | 500 | 350–600 |
| `stagger_ms` | шаг между соседними айтемами | 1000 | 800–1400 |
| `count_ms` | рост числа/шкалы | 2000 | 1200–2500 |

Правила плотности (дублируют AGENTS §8.3):
- шаг `start_time` между айтемами ≥ **800–1000 мс**;
- после последнего айтема ≥ **2000 мс** до перехода к следующему слайду;
- `gap = 0` допустим только как намеренная синхронность (не для «плотной набивки»).

Компонент **не хардкодит** эти длительности — берёт из `motion`. Исключение: длительность
прорисовки графика может быть `appear_ms * k` (k — множитель серии).

## 4. Словарь движения (разрешённые паттерны по архетипу)

| Архетип данных | Паттерн появления | Реализация (compositor-safe) |
|----------------|-------------------|------------------------------|
| Карточки / айтемы / ноды | rise + fade | `opacity 0→1`, `translateY(12px→0)` |
| Бары / столбцы / шкалы | grow from base | `scaleY(0→1)` (origin bottom) или `scaleX` (origin left) |
| Линии / графики | reveal | прорисовка через `opacity` серии (dash-трюк ломается на растянутом SVG) |
| Матрицы / heatmap | cascade | задержка по строке/столбцу: `(row + col) * step` |
| Числа / KPI / проценты | count-up | рост значения за `count_ms` |
| Потоки / связи | edge → node | сначала ребро (opacity), затем нода (scale) |
| Таймлайн | along axis | появление по позиции на оси слева→направо |
| Иконы / образы | gentle fade | только `opacity` (без движения — уважение к образу) |

## 5. Easing (единый набор)

| Назначение | Кривая |
|-----------|--------|
| Появление элемента | `easeOutCubic` = `1 - (1-p)^3` |
| Счётчик / рост | `easeInOutQuad` |
| Непрерывное движение (зацикленное) | `linear` / `sin` |
| Уход/смена | `easeInCubic` |

Больше кривых не вводить без причины; при необходимости — добавлять в helper, не в компонент.

## 6. Composable `useMotion` (план)

Единая точка вместо копипасты. Компонент:

```js
import { useMotion } from '../../composables/useMotion'
const { reveal, count, grow, stagger } = useMotion(relativeTime, motion)
```

API:

| Метод | Возвращает | Назначение |
|-------|-----------|-----------|
| `reveal(item, i, opts)` | `{ opacity, transform }` | карточка/нода: rise+fade |
| `grow(item, i, axis)` | `{ transform, transformOrigin }` | бар: `scaleY`/`scaleX` от базы |
| `draw(item)` | `{ opacity }` | линия/серия: прорисовка |
| `count(target, item, fmt)` | `number \| string` | число, растущее за `count_ms` |
| `stagger(i, extra=0)` | `number` (ms) | `start_time ?? i*stagger_ms` |
| `cascade(row, col)` | `number` (ms) | задержка ячейки матрицы |

`opts`: `{ y = 12, scale = null, delay = 0 }`.

Правило: если компоненту нужна анимация вне словаря §4 — сначала расширяем `useMotion`,
потом используем. Хардкод easing в компонентах после ретрофита запрещён.

## 7. Уважение к теме

- Длительности — из варианта (медленный «candle» для религиозной темы, быстрый «tech»).
- `useMotion` не знает про цвета/тему, только про время.
- При `prefers-reduced-motion` (если появится) — `appear_ms`/`count_ms` → 0, паттерн → мгновенный.

## 8. Ретрофит (план работ)

1. Добавить `core/src/composables/useMotion.js` + юнит-тесты на детерминизм (seek → тот же кадр).
2. Задокументировать §4 в `docs/animation_guidelines.md` (ссылка на этот файл).
3. Ретрофит **Tier 0 примитивов** (10) — эталон.
4. Ретрофит доменных (32) и старых компонентов (50) — по архетипу из §4.
5. Проверка: покадровый аудит (шаг ~200 мс) — число видимых элементов монотонно растёт,
   ни один элемент не «мигает»; финальный кадр = полный.

## 9. Критерии приёмки

- 0 вхождений `requestAnimationFrame` / `infinite` / `<animate` в `core/src/components`.
- 0 хардкоженных длительностей анимации вне `useVariant().motion`/`useMotion`.
- Одинаковый кадр при seek и realtime (скриншот-диф).
- Ритм меняется сменой `style_variants.config.motion` без правки компонентов.
