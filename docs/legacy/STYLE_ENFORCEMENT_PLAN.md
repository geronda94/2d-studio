> 2026-09-18. Пользователь: «3 ошибки до сих пор висят». Ниже — первопричины (не симптомы)
> и многоуровневый план. Принцип: сначала докажи корень, потом чини; каждый уровень — приёмка.

## Диагноз (первопричины)

### R1. Варианты/скругления «не применяются»
- **В кабинете:** превью-стенд НЕ использует конфиг варианта. `previewVariant` привязан к
  `<select>`, но нигде не читается; стенд рисуется Tailwind-классами `rounded-xl/rounded-full`.
  → переключение конфига визуально ничего не меняет (нет обратной связи).
- **В реальных слайдах:** механика ЦЕЛА (30 компонентов читают `var(--item-radius)` из `useVariant`).
- **Селект «Конфиг»** менял только `projects.default_variant` (дефолт для НОВЫХ презентаций),
  существующие не трогались до кнопки «Всем ▶» (добавлена позже, но превью всё равно молчит).
- Итог: чинить надо ОБРАТНУЮ СВЯЗЬ в кабинете + честность модели «дефолт vs применить».

### R2. Иллюстрация перекрыта фоном
- Слои сцены (`bg-image`, `bg-decorations`, `bg-overlay`) лежат на `.slides-container` (чтобы
  быть full-frame и не сжиматься safe-zone).
- `Slide.vue` красит непрозрачный `var(--surface-bg)`; slides идут в DOM ПОСЛЕ слоёв сцены →
  перекрывают их. Видно только у `derevnya` (surface transparent).
- Итог: слайд не должен быть непрозрачной стеной. Фон-база — на контейнере, слайд прозрачен,
  контент/айтемы — выше. Иллюстрация всегда между базой и контентом.

### R3. Библиотека палитр на главной
- Скрыта `v-if="false"`, но не удалена; в отдаваемом Vite коде присутствует. Нужно удалить
  разметку+мёртвый код, затем hard-reload (браузерный кэш dev-модуля).

## L7. Палитра/конфиг на уровне ПРЕЗЕНТАЦИИ + REPLACE-семантика — DONE (2026-09-18)

Проблемы, найденные пользователем:
1. Лес «застревал» при смене палитры — copy **добавлял** ключи источника, не убирая лишние,
   поэтому структурные токены прошлой темы (лес) оставались.
2. Палитра была только проектной — стилизация одной презентации задевала все в проекте.
3. `get_presentation_tokens` **не передавал** `presentation_id` в `_merge_tokens` — слой
   презентации игнорировался.

Реализовано:
1. `presentations.palette_source` (+миграция) — источник палитры презентации.
2. `get_presentation_tokens` → мерж `global→project→presentation` (+ `palette_source`,
   `presentation_tokens`).
3. Новые эндпоинты: `PUT /presentations/{id}/tokens` (точечная правка), `DELETE .../tokens/{key}`,
   `POST .../palette/copy` (в presentation-scope), `POST .../palette/clear` (сброс managed,
   кастомы целы).
4. **REPLACE-семантика copy** (проект и презентация): managed-токены, которых нет в палитре-
   источнике, удаляются → иллюстрация/градиенты меняются ВМЕСТЕ с палитрой, не застревают.
5. UI: `PresentationSettingsModal` — секция «Палитра презентации» (выбор из библиотеки, «Взять»,
   «↩ сбросить к проекту»); `palette-changed` → перезагрузка темы в `MainPresentation`.
6. Восстановление данных: it2b project очищен от деревенской палитры (managed), канон досеян;
   p20 сброшен на tech (лес убран). Кастомы (1312) сохранены.
7. Приёмка: copy tech в p20 → `removed: 4`, forest=False, bg=#0B1322; застрявшего леса нигде
   нет (кроме проекта derevnya/template-derevnya); p4/p13=30/30; фронт 200.

## L8. Варианты не управляют цветом — DONE (2026-09-18)

Жалоба: после выбора classic «многие цвета стали оранжевыми».
Первопричина: `.variant-classic h1 em { color: var(--brand-orange) }` в `style.css` — вариант
ЖЁСТКО задавал хью. Для палитры it2b `brand-orange=#EA580C`. Это нарушение разделения осей
(вариант = материал/форма, палитра = цвет).
Фиксы:
1. Удалено правило `.variant-classic em/span { color: brand-orange }` → classic наследует
   базовое палитро-правило (`--brand-light-blue`). Теперь `<em>` всегда из палитры.
2. Убран `line.color` из всех 5 конфигов `seed_variants.py` (industrial диктовал `color-warning`
   = амбер, educational — `color-success`); линии стали палитро-зависимыми (`useVariant` fallback
   `--brand-light-blue`). Пересеяно.
3. Правило зафиксировано в `AGENTS.md §10`: варианты не задают цвета (кроме стекла/неона);
   tech может менять обработку `<em>` градиентом — но только из токенов палитры.
Проверка: в отдаваемом `style.css` нет `variant-classic em`; в БД ни у одного варианта
`line.color` нет; tech-градиент (палитро-токены) на месте.
Прим.: «классический выбираю — не меняется» — селект = дефолт для НОВЫХ; существующим —
кнопка «Всем ▶» (пользователь нашёл её). Превью-стенд реагирует сразу (L1).

## L9. Градиент `<em>` глобальный — DONE (2026-09-18)

Жалоба: в classic заголовок сплошной (`brand-light-blue`), а должен быть градиент как в tech.
Причина: градиент был привязан к `.variant-tech`; без tech-класса падало на базовое сплошное.
Фикс: градиент (оба цвета — токены палитры) вынесен в базовое правило `h1/h2/h3 em/span`,
`.variant-tech`-скоупинг удалён. Теперь смена варианта не трогает обработку заголовков.
Проверка: в отдаваемом CSS градиент без variant-скоупа.
