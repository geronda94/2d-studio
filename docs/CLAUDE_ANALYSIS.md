# Анализ и вердикты по проекту SceneEngine
*Архитектурный аудит, стратегия качества моушн-дизайна и конвейер генерации с DeepSeek*

**Автор анализа:** Claude (Anthropic)  
**Дата:** 23 октября 2026 г.  
**Целевой контур:** Конвейер потокового производства 2D motion-сцен и передач для YouTube-канала «Механизм» с DeepSeek в качестве ИИ-мозга.

---

## 1. Суть проекта и стратегическая цель

**SceneEngine** — специализированный движок для создания **детерминированных 2D motion-сцен** кинематографического уровня на потоке.

- **Вход:** Сценарий / смысловые блоки передачи.
- **Мозг (ИИ):** DeepSeek (разбивка на сцены, выбор окружений и актеров, генерация HTML/CSS/JS кода сцен).
- **Исполнительный контур:** Sandboxed iframe с контрактом `window.scene.seek(t)`, локальный GSAP и SceneKit.
- **Контроль:** Human-in-the-loop (утверждение сториборда, превью в редакторе, валидация правил).
- **Выход:** Готовый MP4 (16:9 для горизонтального выпуска, 9:16 для Shorts/Reels) без ручной сборки в Adobe After Effects.

---

## 2. Что сделано правильно (Архитектурный фундамент)

1. **Контракт времени `seek(t)`**:
   - Время внешнее, сцена — чистая функция от миллисекунд $t$.
   - Полное устранение рассинхрона аудио и видео, идеальный скрабинг в таймлайне и воспроизводимость любого кадра.
   - Полный запрет недетерминированных API (`requestAnimationFrame`, `Date.now`, `setInterval`, бесконечные CSS `@keyframes`).

2. **Изоляция исполнения (Sandboxed Iframe)**:
   - Атрибут `sandbox="allow-scripts"` без `allow-same-origin` надежно изолирует родительское приложение от генерируемого кода.
   - Инжекция CSS-токенов темы через `srcdoc` обеспечивает стилевое единство.

3. **Компактный SceneKit (`core/public/vendor/scene-kit.js`)**:
   - `cues(list)` + `integrate(key, t)`: непрерывный интеграл скорости предотвращает фазовые рывки колес и механизмов при смене скоростей.
   - `camera(layers, opts)`: 2.5D многослойная камера с независимыми коэффициентами глубины `depth`.
   - `scatter(root, opts)`: детерминированное псевдослучайное размножение объектов (PRNG `mulberry32`).
   - `compose`, `mechanism`, `views`, `visemeAt`.

4. **Самообучающийся конвейер (`scene_learnings`)**:
   - База данных и API реестра ошибок (`GET/POST /scene-library/learnings`).
   - Ошибки кодируются в правила, которые ИИ обязан учитывать перед генерацией.

5. **Качественный прецедент в продакшене**:
   - Шаблон `prav-studio-host` демонстрирует полноценный broadcast-уровень: 70 частиц золотистой пыли на Canvas, объемный световой луч (light sweep), стекло с `backdrop-filter: blur(12px)`, многослойный передний план стола (микрофон, бумаги, кофе) и 2.5D дрейф камеры.

## 3. Анализ контекста и осознанных проектных решений

В ходе технического аудита были выделены аспекты, которые для типового CRUD-сервиса считаются долгом, но **в текущем контексте являются осознанными инженерными решениями автора**:

1. **Snapshot ревизий без полей сцен (`code`, `props`)**:
   - В текущей фазе код сцен версионируется и восстанавливается через Git и сид-скрипты, а база данных служит оперативным хранилищем активной рабочей сессии.
2. **Realtime-захват экрана (Xvfb + Chromium + ffmpeg x11grab)**:
   - Решение выбрано сознательно для быстрого запуска сквозного конвейера без необходимости сложного покадрового экспортера на первой фазе. Конвейер уже успешно выдает 30 fps MP4 видео (`Prav_Studio_demo`).
3. **Эволюция схемы БД без Alembic (`_ensure_columns`)**:
   - Позволяет мгновенно прототипировать новые метаданные и поля без накладных расходов на миграционные файлы в период быстрой смены структуры сцен.

## 4. Главный фокус: Почему сцены выглядели «средне» и как выйти в ТОП

### Разрыв: «Инженерный код» vs «Кинематографический моушн»

Аудит 15 шаблонов библиотеки показал ключевой парадокс:
- **Архитектура превосходная**, но большинство библиотечных шаблонов написаны как **учебные математические демки** на чистом JS: линейная смена скоростей, тригонометрические синусы на поворот колес и отсутствие атмосферных слоев.
- Библиотека GSAP подключена в рантайм, но в шаблонах практически **не использовалась**.

### 7 обязательных компонентов premium-качества 2D сцен

1. **GSAP Timelines вместо «сырых» формул**:
   - Использование `gsap.timeline({ paused: true })` с привязкой `window.scene.seek = (t) => tl.seek(t / 1000)`.
   - Замена ступенчатой скорости на асимметричные кривые ускорения: взрывной разгон (`power4.out`, `expo.out`) и мягкий инерционный хвост (asymptotic settle).
2. **Атмосферные частицы (Deterministic Canvas Particles)**:
   - Векторная графика без микрочастиц выглядит плоской и «веб-страничной».
   - В каждой уличной, природной или студийной сцене должен присутствовать холст с детерминированными частицами (пылинки в лучах света, снежинки, искры, споры).
3. **Пост-обработка: Film Grain + Vignette + Color Grade**:
   - Обязательный слой `.layer-fx` с SVG-фильтром шума (`feTurbulence`), виньеткой и двухтоновым оверлеем (`mix-blend-mode: soft-light`). Это связывает векторные цвета в единую цветовую гамму кадра.
4. **Заземление и контактные тени (Contact Shadows)**:
   - Персонажи, автомобили, столы и здания не должны «висеть в воздухе». Обязательны двойные эллиптические тени (жесткое пятно контакта + мягкая полутень).
5. **Кинетическая типографика (Kinetic Typography)**:
   - Запрет на простое появление текста через `opacity: 0 → 1`.
   - Применение масок переполнения (`overflow: hidden`), посимвольного/построчного выдвижения (`stagger`) и динамического стягивания межбуквенного расстояния (`letterSpacing`).
6. **Вторичное движение (Secondary Motion & Micro-Rigging)**:
   - Деревья на заднем плане должны слегка покачиваться на ветру.
   - Портреты персонажей должны иметь рассинхронизированные циклы дыхания, микродрейфа взгляда и периодического моргания (каждые 3.5–4 секунды).
7. **2.5D многоплановость (Multi-Plane Parallax)**:
   - Минимум три плана: Foreground (крупные размытые объекты на переднем крае, глубина 1.4–1.8), Midground (актеры и фокус, глубина 1.0), Background (пейзажи и архитектура, глубина 0.1–0.4).

## 5. Стратегия работы с DeepSeek в качестве ИИ-мозга

Для того чтобы DeepSeek выдавал качественные сцены **на потоке без деградации**, взаимодействие выстраивается по строгому инженерному протоколу:

### 1. Жесткий JSON Schema контракт
DeepSeek получает входную спецификацию и возвращает строго типизированный JSON (без markdown-рассуждений вокруг):
```json
{
  "html": "<div class=\"scene\">... обязательные 5 слоев ...</div>",
  "css": ".scene { ... vw/vh единицы, токены темы, post-grain ... }",
  "js": "const tl = gsap.timeline({ paused: true }); ... window.scene = { seek(t) { tl.seek(t/1000); } };"
}
```

### 2. Принцип Few-Shot на эталонах (Gold Standards)
Модели не объясняются правила абстрактно — ей скармливаются 5 эталонных сцен:
- `outdoor-cinematic`: GSAP timeline, многослойный параллакс, contact shadow, частицы пыли.
- `studio-broadcast`: Canvas dust, свет, стекло, карточка диктора, микро-дыхание.
- `historical-landscape`: SVG архитектура, объемный свет (god rays), качание силуэтов.
- `infographic-timeline`: Кинетическая типографика, анимированные графики, акцентные маркеры.
- `dramatic-quote`: Свечное мерцание, виньетирование, текстовый ревил.

### 3. Автоматический инжект Learnings
Перед отправкой промпта бэкенд запрашивает `GET /scene-library/learnings?status=active` и подмешивает актуальные табу и правила в системную секцию.

### 4. Автоматическая валидация ответа (Sanitizer)
Перед сохранением в БД скрипт проверяет код через AST/RegEx:
- Отсутствие `requestAnimationFrame`, `Date.now`, `setInterval`, `Math.random` без seed.
- Наличие `window.scene = { seek }`.
- Наличие 5 стандартных слоев (`layer-world`, `layer-objects`, `layer-actors`, `layer-fx`, `layer-overlay`).

## 6. Расширения SceneKit (Инструменты для ускорения)

Рекомендовано дополнить `core/public/vendor/scene-kit.js` готовыми детерминированными утилитами, чтобы DeepSeek не генерировал громоздкий бойлерплейт:

1. **`SceneKit.particles(canvas, opts)`**:
   - Готовый генератор детерминированных частиц (пыль, снег, искры) на базе `mulberry32`.
2. **`SceneKit.idle(characterEl, opts)`**:
   - Автоматический расчет дыхания, покачивания и моргания для фото-портретов и SVG-персонажей.
3. **`SceneKit.postFx(container, opts)`**:
   - Автоматическая инжекция film grain, vignette и color-grade оверлеев.
4. **`SceneKit.ease`**:
   - Библиотека кастомных кинематографических кривых для GSAP и CSS.

**Итоговый вердикт:**  
Движок SceneEngine имеет **отличную архитектурную базу**. Переход от «инженерных прототипов» к «кинематографическому моушн-дизайну на потоке» достигается не переписыванием платформы, а внедрением **GSAP-таймлайнов, обязательных атмосферных слоев (зерно, виньетка, частицы, тени) и эталонного few-shot промптинга для DeepSeek**.
