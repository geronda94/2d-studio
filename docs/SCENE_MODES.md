# SCENE_MODES — сцены с нуля vs переиспользование

Главная мысль: **переиспользование — это удобство, а не ограничение**.
Большинство сцен может быть написано с нуля новым кодом. Библиотека нужна
для персонажей, миров/фонов и повторяющихся объектов.

---

## 1. Два режима

### `mode: "code"` (по умолчанию для сложных сцен)
- Источник истины — `code.html/css/js`.
- Никакой обязательной композиции из объектов.
- Можно использовать `SceneKit`, камеру, SVG, Canvas, WebGL, что угодно.
- Редактор всё равно даёт Layers/Cues/Props/Code.
- Переиспользование — опционально: скопировать код мира/персонажа или
  подключить asset.

### `mode: "composite"`
- Сцена собирается из `world + objects + cast + cues`.
- Билдер генерирует `code`, который остаётся источником истины для рендера.
- Удобно для быстрых сцен, фонов, повторяющихся форматов.
- Можно в любой момент «развернуть» в код и править вручную.

Оба режима рендерятся одним `SceneHost` и `seek(t)`. Разница только в том,
кто автор кода — человек/ИИ или билдер.

---

## 2. Что переиспользуем

| Сущность | Переиспользование | Почему |
|---|---|---|
| Персонажи | высокое | один ведущий/соведущий во многих сценах |
| Миры/фоны | высокое | лес/город/офис повторяются |
| Пропсы/объекты | среднее | машина, стол, фонарь |
| Уникальные сцены | низкое | лучше писать с нуля под смысл |

Проект может иметь **свой каст**:
```json
{
  "cast": {
    "host": { "character": "host-1", "outfit": "casual" },
    "cohost": { "character": "cohost-1", "outfit": "studio" }
  },
  "worlds": ["forest", "city", "office"]
}
```
Сцена может ссылаться на `cast.host` или использовать свой код.

## 3. Как делать «3D-вид» без 3D-движка

2.5D-камера на HTML/CSS:
- `perspective` на `.scene`;
- слои с разной `depth`;
- `SceneKit.camera` двигает слои: `translate3d + scale + rotate`;
- параллакс: дальние слои двигаются меньше;
- свет/тени/виньетка/туман — CSS-слои;
- DOF/motion blur — предразмытые слои или выборочный `filter: blur`;
- частицы/пыль — Canvas или CSS.

Пример:
```js
const cam = SceneKit.camera([
  { el: sky, depth: 0.15 },
  { el: mountains, depth: 0.35 },
  { el: pinesFar, depth: 0.55 },
  { el: pinesNear, depth: 0.8 },
], {
  path(t) {
    return {
      x: Math.sin(t / 2600) * 26,
      y: Math.cos(t / 3400) * 10,
      z: -t * 0.01,
      zoom: Math.sin(t / 4200) * 0.02,
      rot: Math.sin(t / 5000) * 0.5,
    }
  },
})
```

Это даёт «камеру», глубину и движение, которые читаются как 3D.
Настоящий 3D (Three.js/WebGL) — отдельный тип сцены на будущее, не обязательный.

Готовый пример: шаблон **`cinematic-forest`** (2.5D-камера, свет, виньетка,
параллакс, машина).

## 4. Как это встраивается в текущий механизм

```
SceneHost (iframe)
  ← code.html/css/js (всегда)
  ← props, cues, view
  ← window.scene.seek(t)
```

- Нет требования «сцена = объект + мир».
- `mode` — просто метка для редактора/ИИ.
- Layers парсит `.obj-*`, если они есть; если нет — показывает код.
- Cues работают всегда.
- Камера — обычный JS-хелпер, не часть рантайма.

---

## 5. Что добавить в данные

- `scene.mode`: `code` | `composite`.
- `scene.world`: slug мира (опционально).
- `scene.cast`: ссылки на персонажей проекта (опционально).
- `project.cast`: JSON с ведущим/соведущим.
- `project.worlds`: список миров проекта.

Пока можно хранить в `props`/`data.payload`; отдельные колонки — позже.

---

## 6. Правила для ИИ

- Если сцена уникальная — пиши с нуля, не заставляй её собираться из объектов.
- Если нужен повторяющийся персонаж/мир — используй каст/мир проекта.
- Не дублируй 50 деревьев — `SceneKit.scatter`.
- Для «3D-вида» используй камеру/слои/свет, а не плоский zoom.
- Не превращай каждую сцену в конструктор из карточек.
