## 0. 2D-first, 3D frozen (2026-10-27)

- Production-персонажи — Canvas 2D `PaperCast`, не GLB/Babylon.
- 3D-код и ассеты — только `drafts/3d/`; не импортировать в `core/public`.
- **Правило:** у каждого `ctx.save()` в Canvas-риге должен быть парный
  `ctx.restore()` в том же слое. Утечка transform сдвигает следующие части
  (у Mira серёжка уехала на 140 px в сторону).
- **Правило:** не растягивать canvas CSS-аспектом. `PaperCast` сам
  вписывает 600×900 в контейнер через `min(w/600,h/900)` и центрирует.
- **Правило:** для брюк не рисовать широкий «фартук» между ног. Лучше
  свести бёдра и оставить узкую щель, чем имитировать ткань клином.

# LEARNINGS — реестр ошибок и правил

Цель: каждая найденная ошибка превращается в правило, которое ИИ читает
перед генерацией и не повторяет.

---

## 1. Где хранится

Два уровня:
- **БД** `scene_learnings` + API `/scene-library/learnings` (машиночитаемо).
- **Этот файл** — человекочитаемый обзор и процесс.

Модель:
```json
{
  "category": "visuals",
  "symptom": "Editor preview is black",
  "cause": "Theme variables not injected",
  "fix": "Fallback to .slides-container + defaults",
  "rule": "SceneHost must work outside .slides-container",
  "scene_ref": "scene-demo-1",
  "tags": ["editor", "theme"],
  "status": "active",
  "source": "ai"
}
```

Категории:
`determinism`, `layout`, `compatibility`, `visuals`, `audio`, `process`, `performance`.

---

## 2. Процесс

### Перед генерацией
1. `GET /scene-library/learnings?status=active`
2. Прочитать правила категории.
3. Учесть в коде/сцене.

### Статусы
- `proposed` — предложено ИИ, ещё не правило.
- `active` — утверждено человеком, используется.
- `archived` — устарело.

`POST /scene-library/learnings` с `source=ai` создаёт `proposed`.
Человек утверждает: `POST /scene-library/learnings/{id}/approve`.
Архив: `POST /scene-library/learnings/{id}/archive`.

### После QA / ревью
1. Найти ошибку.
2. Исправить.
3. Добавить запись `POST /scene-library/learnings`:
   - symptom — что видно;
   - cause — почему;
   - fix — как исправили;
   - rule — как не повторить;
   - tags/category.
4. Если правило уже есть — не дублировать, а обновить/уточнить.

### На ревью
Человек видит список ошибок и правил; может архивировать (`status=archived`).

## 3. Начальные записи

| Категория | Симптом | Правило |
|---|---|---|
| layout | `querySelector` null в iframe | Сцена всегда в `<div class="scene">` |
| process | Seed обновил не ту сцену | Искать по `slide_id`, не `.first()` |
| visuals | Чёрное превью редактора | Тема + дефолтные CSS-переменные вне `.slides-container` |
| visuals | Светлый хром редактора | Задавать `--*-rgb` переменные |
| process | 404 после нового роутера | Рестарт backend + curl |
| process | `git push` refspec main | `git branch -M main` |
| process | Утечка infra-доков | Проверять staged files перед push |
| visuals | `view` не доходит | Проверить всю цепочку до CSS |
| compatibility | Фонарь в офисе | `domain/environments` + фильтр |
| process | Cues не влияют | Шаблон читает `window.__sceneCues` |
| determinism | Анимация «плывёт» | Только `seek(t)`, без rAF/Date.now |
| performance | Тяжёлый blur | Предразмытые слои, transform/opacity |

## 5. Что считать хорошей записью

- Симптом воспроизводим.
- Причина конкретна (файл/поле/шаг).
- Исправление проверено.
- Правило короткое и применимое к будущим сценам.
- Есть теги/категория.

Плохо: «сцена сломалась, починили».
Хорошо: «`root` null, потому что HTML не обёрнут в `.scene`; правило: всегда оборачивать».

## 7. Персонажи: руки и локти (обязательное правило)

### Симптом
Пользователь видит «руки вывернуты назад»; ладонь/пальцы смотрят за спину,
особенно в talk-позе и при взгляде сбоку.

### Причина (три независимые ошибки)
1. `add_oriented_sphere` для ладони получал `y_axis=(0, 1, 0)` для обеих рук.
   У левой ладонь смотрела к бедру, у правой — наружу. Нужен зеркальный
   `y_axis=(0, sx, 0)`.
2. `rotate_mesh(hand, palm_c, d, 32°)` — дополнительный roll вокруг оси руки
   уводил пальцы назад. Никакого roll не нужно: плоскость ладони уже задана
   ориентацией эллипсоида.
3. В `scene-rig.js` `lowerArm` имел положительный X в talk-позе. Для этого
   скелета положительный X сгибает локоть **за спину**. Натуральный сгиб —
   отрицательный X.

### Правило
- Ладонь: `add_oriented_sphere(..., d, (0, sx, 0))`.
- Пальцы: вниз по предплечью, большой палец вперёд (`-Y`).
- Никаких `rotate_mesh` вокруг оси руки.
- В рантайме: `lowerArm` X < 0 (вперёд), X > 0 запрещён.
- Плечо: рукав из 3 колец с весами `shoulder/chest → shoulder/upperArm → upperArm`.
  Патч на 100% `upperArm` при подъёме становится шаром; если патч нужен — 50/50.
- Проверка: рендер обеих рук сбоку (`+X` и `-X`) в rest и talk;
  wave — дополнительно сзади (`+Y`) и в 3/4.


## 8. Hero-риги: T-pose и наклон головы

- Импортированные hero-меши (Avatar SDK, RPM) часто стоят в **T-pose**, а не
  в A-pose. Локальный Euler по `upperArm` только скручивает/уводит руку
  вперёд. Правильно: повернуть вокруг **мира Z** с пересчётом через
  родителя: `local = parentQ⁻¹ · Rz · parentQ · rest`.
- Голова у этих же ригов лежит с наклоном; локальные `x`-смещения дают
  «смотрит в потолок». Вводится `headPitch` как калибровка rest-позы;
  анимационные наклоны головы для hero-ригов лучше не задавать локальным
  Euler без отдельной проверки.
- Отображать HD-базу и процедурную базу как два класса: у HD фиксированный
  гардероб/идентичность, у процедурной — параметры и массовка.


## 9. Hero-одежда и кисти: не путать базу и не крутить предплечье

- Старая процедурная `Mark` без бороды и с грубыми плечами — это **не**
  HD. Если селектор показывает `Mark`, а не `Mark HD`, сцена грузит
  процедурную базу. Алиасы `mark`/`mira` должны указывать на HD; старые
  базы — только `mark_custom`/`mira_custom`.
- Рукав Avatar SDK при полном опускании руки из T-pose собирается в
  валик у дельтовидной мышцы. Помогает: (1) распределить `armRestZ`
  ~20% на `shoulder` и ~80% на `upperArm`; (2) заменить верх/низ на
  ассет с нормальной посадкой и складками.
- Кисть нельзя «крутить» вместе с плечом: это уводит предплечье вперёд
  или за спину. Вращать надо **только `hand`** вокруг оси `hand → middle1`
  (wrist twist). Проверять full-body спереди: ладонь к бедру, wrist на
  месте, пальцы вниз.
- Для HD-одежды материал называется `outfit_top`/`outfit_bottom`, а не
  `Top`/`Bottom`; цветовые swatch'и Studio её не перекрашивают. Держать
  swatch в тон фактической одежды, иначе UI врёт.
- Кэш `scene-rig.js` версионируется в `character-studio.html` и
  `core/src/scenes/runtime.js`; при правке рантайма поднимать обе версии.

## 10. Canvas-риг: `save()` и ранний `return`

### Симптом
Одна поза (`heart`) ломает весь кадр: торс висит прямоугольником, голова и
ноги уезжают. На следующих кадрах состояние не восстанавливается.

### Причина
В ветке рисования кисти был ранний выход:
`ctx.restore() → ctx.save() → … → return` без второго `restore()`.
Стек `save` утекал: трансформ кисти оставался активным, и всё, что рисовалось
после (голова, ноги), смещалось. Каждый вызов `draw` добавлял ещё один слой.

### Правило
- На каждый `save()` — ровно один `restore()`, в том числе на всех ветках
  с `return`.
- Если нужен абсолютный трансформ внутри вложенного `save`, делать
  `restore()` → `save()` → рисовать → `restore()` → `return`.
- Проверка: после позы вернуть `neutral` на том же инстансе и сравнить кадр
  с чистым `neutral` при том же `t`; хеши должны совпасть.

## 11. Canvas-риг: конечности — трубы, не конусы

### Симптом
Скелет собран, позы работают, но персонаж «состоит из конусов»: каждое
плечо/локоть/колено — отдельный усечённый конус, на стыках видны швы и
круглые joint-диски. Силуэт читается как набор деталей, а не как тело.

### Причина
Кость рисовалась двумя `tapered(a, b, r1, r2)` + `jointDisc` в точке сгиба.
Даже с одинаковыми радиусами на стыке получаются два торца, шов и «перелом»
конуса; при сгибе локтя конусы расходятся и обнажают стык.

### Правило
- Рука и нога — **одна непрерывная труба** по polyline:
  `limb(ctx, [плечо, локоть, запястье], [r0, r1, r2], …)`.
  `limb` строит нормали в каждой точке, сглаживает радиус и закрывает
  концы круглыми caps; швов и дисков нет.
- Не возвращать `tapered`-сегменты + `jointDisc` для рук/ног. `tapered`
  допустим только для шеи.
- Радиусы задавать от плеча к запястью (16→14→9.5) / от бедра к щиколотке
  (31→25→23→16); не делать резких скачков — будет «сосиска».
- Одежда рисуется поверх той же трубы (короткий рукав — вторая труба
  поверх плеча + манжета), а не отдельной костью.
- Манжета — полоса **поперёк** конечности: `rotate(angle - PI/2)`, ширина
  по диаметру трубы. Если повернуть на `angle`, получается «пластырь»
  вдоль руки (было в v5).
- Проверка: `neutral` в нативном разрешении (600×900) — на руках и ногах
  нет видимых стыков; контактный лист всех 31 позы.
