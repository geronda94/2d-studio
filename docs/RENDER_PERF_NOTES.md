> Статус: **наблюдение зафиксировано, оптимизации НЕ внедрялись** (отложено). Вернуться,
> если фризы станут заметны на выходном видео. См. также `render_fullscreen_capture.py`,
> `routers/renders.py`, `RenderManagerModal.vue`.

## Что наблюдается

- При рендере есть небольшие фризы анимации. На локальном ПК результат «более-менее терпимый».
- Заметнее всего на **непрерывных** анимациях, в частности на двух компонентах проекта
  `p/44` (Diademas): `PortraitLampSlide` (лампадка + блик оклада) и `TimelineSlide`
  (заполнение шкалы, переключение событий).

## Механика рендера (почему это важно)

- Realtime-захват: Playwright (`headless=False`) открывает `/p/{id}?render=true`, параллельно
  `ffmpeg` пишет экран через **x11grab** (+ звук pulse). См. `backend/render_fullscreen_capture.py`.
- Chromium запускается с **`--disable-gpu`** → растеризация **софтверная** (без GPU),
  `render_fullscreen_capture.py` (launch args).
- Частота по умолчанию **60 fps** (`RenderManagerModal.vue` → `fps=60`; `renders.py:152` берёт
  из настроек джобы). Размеры: ландшафт `1920×1280`, портрет `1280×1920`, desktop `1920×1080`.
- Слайды в DOM все, но неактивные скрыты через `v-show` (`Slide.vue`), т.е. рисуется только
  активный. `relativeTime` каждого слайда = `currentTime − startTime` и меняется каждый кадр.
- Бюджет кадра при 60 fps ≈ 16.6 мс. Что не уложилось — кадр дублируется → «фриз».

## Почему страдают именно некоторые компоненты

Большинство компонентов анимируют **дискретно** (появление айтемов по `start_time` — единичные
изменения), поэтому на 60 fps выглядят гладко. А эти — **непрерывно, каждый кадр**:

- `PortraitLampSlide` (`core/src/components/slides/PortraitLampSlide.vue`):
  - бегущий блик оклада `sheenX` считается каждый кадр (через `transform`, это ок);
  - `Lampada` (`core/src/components/ui/Lampada.vue`): качание/мерцание каждый кадр + **`filter: blur(50px)`**
    на ауре (`~280×320`) внутри **вращающегося** контейнера; SVG `feGaussianBlur` на пламени.
    В софтверном режиме `blur`, пересчитываемый каждый кадр, — самый дорогой эффект.
- `TimelineSlide` (`core/src/components/slides/TimelineSlide.vue`):
  - заполнение шкалы уже через `transform: scaleX` (ок);
  - но точки используют **`transition-all`** → анимируют `width/height` (layout) и `box-shadow`
    (paint) при смене активного события.

## Замеры (индикативно, софтверно, `headless + --disable-gpu`, 1920×1080)

Harness шумноват (состояние play/пауза, фоновая нагрузка), поэтому цифры — ориентир, не эталон:

| Слайд (p/44)      | fps (avg) | кадров > 33 мс |
|-------------------|-----------|----------------|
| MetricScales (контроль) | ~60  | 0–1            |
| TimelineSlide     | ~51       | 33 из 219      |
| PortraitLampSlide | 29–60 (разброс) | 0–35; в «плохом» прогоне p95 ≈ 117 мс, max ≈ 200 мс |

Вывод: `TimelineSlide` стабильно не дотягивает до 60 → на 60-fps захвате видно дёрганье;
`PortraitLampSlide` даёт длинные кадры из-за `blur`, особенно под нагрузкой ffmpeg/захвата.

## Вероятная причина (не баг компонента)

Совокупность: софтверный рендер (`--disable-gpu`) + 60 fps захват + непрерывные per-frame
анимации с дорогими `blur` / layout (`width/height`) / `box-shadow`. На сервере под нагрузкой
(несколько рендеров/агентов) картина хуже, чем в изолированном замере.

## Идеи (если начнём чинить — НЕ реализовано)

1. `Lampada`: уменьшить `blur` (напр. 50px → 20–24px) и/или обновлять ауру реже (10–15 Гц вместо
   каждого кадра), либо заменить на статичный/pre-rendered glow.
2. `TimelineSlide`: убрать `transition-all` с точек → анимировать `transform: scale()` + `opacity`
   (композитно), не трогать `width/height/box-shadow`.
3. Опционально: для «тяжёлых» тем рендерить в **30 fps** (меньше нагрузка, джаддер continuous-анимаций
   мягче) либо разрешать GPU (`--use-gl=...`) там, где он есть.
4. Измерить в **реальном** рендере «до/после»: 10–15 сек клипов этих слайдов с временно
   отключёнными `blur`/`transition` и сравнить; либо трассировка Chrome (Paint/Raster по времени).

## Как воспроизвести замер

- Софтверный прогон: Playwright `chromium.launch(args=["--disable-gpu"])`, открыть `/p/44`,
  перейти на слайд через сайдбар (`S`), `window.useDirectorInstance.play()`, замерить интервалы
  `requestAnimationFrame` (~220 кадров, отбросить первые ~40).
