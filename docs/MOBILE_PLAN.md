# План мобильной адаптации и управления

> 2026-09-19. Цель: удобно и управляемо с телефона, без переизобретения — через
> масштабирование по пропорциям экрана (fit-by-scale) + touch-управление.

## 1. Диагноз (по коду)

| Проблема | Где | Последствие |
|---|---|---|
| `w-screen h-screen` = `100vw/100vh` | `SlidePresentation.vue:3`, `MainPresentation.vue:5,68` | на телефоне `100vh` больше видимой области (адресная строка) → преза вылезает за экран |
| Масштаб считается от `container.clientWidth/Height` | `SlidePresentation.vue updateScale:847` | контейнер в `vh`, а не в видимой области → overflow |
| **Нет touch-обработчиков** | в плеере 0 `@touch*` | нельзя свайпать/тапать осмысленно |
| Пилюля контролов только на hover | `SlidePresentation.vue:~343` `opacity-0 group-hover/panel:opacity-100` | на тач-экране hover нет → контролы **не видны/не доступны** |
| Модалы фикс-ширины | `SlideEditorModal` `w-[500px]`, `RenderManagerModal` `max-w-4xl` | на телефоне тесно/мелко/вылезает |
| Админка: `p-6 md:p-12`, сетки ок, но кнопки мелкие | Home/Project/Folder/AppShell | тап неудобен |

## 2. Принцип (как предложено)

**Fit-by-scale по пропорциям экрана**, без рефлоу вёрстки:
- Есть базовые размеры полотна: ландшафт `1920×1080`, мобильный `450×800` (уже есть в `updateScale`).
- На клиенте считаем `scale = min(viewportW / baseW, viewportH / baseH)` и применяем `transform: scale()`.
- Поля вокруг = фон темы (`bg-base`), не белые; вёрстка не перестраивается.
- Ключ — измерять **видимую** область (`visualViewport`/`dvh`), а не `100vh`.

Это даёт: преза целиком влезает, ничего не обрезается, одинаково на любом соотношении.

### Исходное описание фаз

### M0. Правильные единицы и метрики (S)
- Заменить `h-screen/w-screen` на `100dvh/100dvw` (fallback `vh/vw`) в плеере и обёртках.
- Слушать `window.visualViewport` (`resize`/`scroll`) и `orientationchange`; высоту/ширину брать из `visualViewport`.
- Учесть `env(safe-area-inset-*)` (вырезы/жесты) — отступы полотна.
- Файлы: `SlidePresentation.vue`, `MainPresentation.vue`, `style.css` (utility `.h-dvh`, `.viewport`).

### M1. Масштаб полотна в плеере (M, ядро запроса)
- `updateScale()`: считать от `visualViewport.width/height` (fallback `innerWidth/Height`), а не от `vh`-контейнера.
- База: `isMobile ? 450×800 : 1920×1080`. `scale = min(...)`, не больше 1 для мобилки/десктопа.
- Полотно центрируется, фон темы заполняет поля; при вращении — пересчёт по `resize`.
- Убрать «вылезание»: контейнер строго `overflow:hidden`, размер = viewport.
- Приёмка: на телефоне (портрет и альбом) преза целиком видна, без обрезки и скролла.

### M2. Touch-управление плеером (M)
- **Пилюля на мобиле:** показывать всегда (не только hover) или по тапу по низу; тап по пустому месту прячет.
- Крупные хит-таргеты ≥ 44px (иконки, пункты дропдаунов).
- **Жесты:** свайп влево/вправо → следующий/предыдущий слайд; тап по центру → play/pause; двойной тап → fullscreen (опц.).
- Дропдауны уже по клику — ок для тача; закрытие по тапу вне (уже есть).
- Приёмка: с телефона можно листать слайды, ставить паузу, открыть экспорт/настройки.

### M3. Модалы как bottom-sheet/full-screen (M)
- `SlideEditorModal`: на мобиле — на весь экран (не `w-[500px]`), внутренний скролл, крупные поля.
- `RenderManagerModal`: одна колонка (форма → очередь), прогресс читаемый.
- `PresentationSettingsModal`, `AiAssistantModal`, `MediaLibraryModal`, `ComponentSelectModal` — `w-full h-full` на мобиле.
- Приёмка: любые настройки открываются и ими можно пользоваться без зума.

### M4. Админка под палец (S–M)
- Уменьшить паддинги на мобиле (`p-4`), кнопки ≥ 44px, карточки в одну колонку (уже есть).
- Таблицы (ModernTable и пр. — контент слайдов, не трогаем) — вне скопа.
- `AppShell`: крошки переносятся, заголовок меньше, действия — в столбик.
- Приёмка: Home/Project/Folder/Настройки удобно с телефона.

### M5. QA на реальном устройстве (S)
- Проверить: портрет/альбом, адресная строка (dvh), вырез (safe-area), iOS Safari и Android Chrome.
- Рендер-смоук не затрагивается (серверный рендер независим от клиентского масштаба).

## 4. Что НЕ делаем (осознанно)
- Не переверстываем компоненты слайдов под мобилку (масштабируем полотно).
- Не меняем серверный рендер и safe-zone.
- Не вводим отдельный «мобильный сайт» — один интерфейс + fit-scale.

## 5. Риски
- iOS `100dvh` и `visualViewport` ведут себя по-разному при скролле — нужен fallback и тест.
- Тач-жесты могут конфликтовать с горизонтальным скроллом таймлайна — свайп только по области слайда, не по таймлайну.
- Появление всегда-видимой пилюли может перекрывать контент на маленьком экране — авто-скрытие через N сек.

## 6. Порядок
M0 → M1 (ядро) → M2 (управление) → M3 (модалы) → M4 → M5.
