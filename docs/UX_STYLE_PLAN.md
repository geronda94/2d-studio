# UX + архитектура стилей: контекст, решения, детальный план

> 2026-09-17. Зафиксировано по итогам двух итераций обсуждения, чтобы ничего не выпало.
> Статус: план, не реализовано (кроме указанного).

## 1. К чему пришли (решения — не пересматривать без причины)

1. **Конфиги стилей (`style_variants`) — глобальные.** Их 5–6, доступны всем.
   В настройках проекта — переназначение дефолтного конфига (`projects.default_variant`).
2. **Цвета (`design_tokens`) — глобальные + индивидуальные.** Привязка уже есть:
   `project_id NULL` = глобальный, задан = только свой проект (мерж `global→project` это учитывает).
   Ничего перестраивать не надо — нужен library-слой сверху.
3. **Проекты = конфиги цветов.** Палитра как сущность = сет токенов проекта.
   Библиотека = проекты-шаблоны (`is_template`); «взять себе» = копирование сета;
   «свой фирстайл» = свой проект + редактор токенов.
4. **Дефолтный поток:** тема проекта → все слайды. Override только явно:
   вариант на слайд (`payload.variant`, UI-пикер), позже — точечные токены слайда
   (`design_tokens.slide_id`, схема уже поддерживает).
5. **«Несколько полных тем на проект» — НЕ строим.** Взрыв сложности без запроса;
   пресетов + per-slide variant достаточно.
6. **Пользователи/мембершип — позже.** Фундамент сейчас: `is_template` + скоупированный мерж
   + copy-потоки. Таблица `project_members` и enforcement — фазой авторизации, не раньше.
7. **Шахматка — только opt-in.** Как дефолт отменена; токены `slide-bg-*` лежат готовые.
   Переключатель — на презентацию, выключено по умолчанию.

## 2. Что уже есть (не строить заново)

- `design_tokens.project_id` (NULL=global), мерж `global→project→presentation→slide`.
- `is_custom` + `DELETE` только custom + single-key PUT библиотеки.
- Пресеты (`style_presets`, `GET/POST/DELETE /presets/`, `PUT /presentations/{id}/style`, lock=422).
- `payload.variant` per-slide (движок резолвит, UI пикера нет).
- Шестерёнка в `SlidePresentation` — заглушка (`alert`, `handleOpenSettings`).
- `ColorLibraryModal` admin-режим (дефолты правит, удалить нельзя).

### STUDIO-11. Стиль и тема — независимые оси + синхронизация стенда — DONE (2026-09-18)

Жалобы: (1) стенд не отражал форму выбранного конфига (у industrial скруглений нет, а показывал tech);
(2) селект палитры пустой вместо текущей темы; (3) непонятно, как применять стиль и тему по отдельности.
Первопричины и фиксы:
1. `previewVariant` — отдельный ref, хардкод `tech`, не следовал за конфигом проекта → стенд
   всегда показывал tech. Фикс: при загрузке `previewVariant = project.default_variant || 'tech'`,
   и синхронизируется при применении конфига. Теперь industrial показывает radius 0 и т.д.
2. `copyFrom` не предзаполнялся → селект «Выбрать…». Фикс: `copyFrom = project.palette_source`.
3. Панель переписана в ДВЕ явные независимые оси: «Стиль (форма): радиусы·границы·тени·линии·моушн»
   и «Тема (цвета): фон·градиент·иллюстрация·цвета». Операции независимы и раньше (variant vs tokens),
   но UI это не показывал. Кнопки: «Применить тему» / «↩ К источнику».
4. Стенд: заголовок «Песочница: примеряй без применения» + селект «примеряю конфиг» + кнопка
   «Применить» (переносит примеренный конфиг в проект). Понятно, что стенд — не применение.

### STUDIO-9. Кабинет: белая плашка + понятность — DONE (2026-09-18)

Нестыковки из скриншотов, разобраны детально:
1. **Белая плашка в тёмном превью** — корень: стенд задавал `--pv-*` (палитра проекта), но конфиг
   варианта резолвит `--item-bg → var(--bg-surface)` — а `--bg-surface` в скоупе стенда НЕ БЫЛО,
   падало на светлую тему страницы настроек. Фикс: `themeVars` — все токены проекта под
   настоящими именами (+`-rgb`) скоупированы корнем стенда. Теперь вариант считается
   в палитре проекта, наружу ничего не течёт.
2. **Непонятно что делать** — панель разбита на «Конфиг формы» / «Цвета» с подписями;
   группы получили описания; сцена: превью ПЕРВЫМ (сверху), строки компактные (длинные
   сворачиваются, ▼ разворачивает в textarea); стенд: рамка + `var(--pv-type-h1)`.
3. По пути: дубль `bg-overlay` в сидах (канон уже имел тёмный оверлей — убран из нового блока,
   иначе `--force` убил бы его); coverage 88/88 после рестарта (бэкенд кэширует канон в импорте).
4. Починен разбаланс тегов (остаток старого блока превью) — добавлен самопроверочный
   python-парсер в процесс (считать только template-блок с правильными смещениями).

### STUDIO-8. Сцена — стандартный набор + REPLACE + чистка it2b — DONE (2026-09-18)

Требование: иллюстрация — стандартная переменная, дефолтная на всех проектах и в сидах, по умолчанию пустая.

   (без glow) + затёр glow в it2b при copy. Фикс: `tokens={**GLOBAL_TOKENS, **IT2B_TOKENS}`.
3. it2b возвращён на tech-канон (copy template-tech): лес/шум/сансет убраны, glow на месте,
   кастом `1312` цел. p4: тёмный `#0B1322`, без леса.
4. По пути удалены мёртвые legacy-ключи 11.09 (`transparent-white-*`, `transparent-black-50`,

5. Замечание: `text-secondary/text-muted` it2b сброшены на global (`#A6B4C8/#6C7C96`) — были
   Managed-отличия неизвестного происхождения; при жалобе — перевыставить через кабинет.

## 4. Как не сломать (обязательно к соблюдению)

1. **Только аддитивные миграции**: `ALTER ... ADD COLUMN IF NOT EXISTS`, новые nullable колонки,
   новые таблицы через `create_all`. Никаких DROP/переименований.
2. **P0-конвенция сидов**: досеив missing по умолчанию, `--force` для значений, кастомы — никогда.
   Новый сид (`seed_presets`-стиль) сразу с `--force` и skip-custom.
3. **API обратно совместимо**: только новые optional-поля/эндпоинты; существующие ответы не менять
   (добавлять ключи можно — клиенты игнорируют лишнее).
4. **Геометрию рендера не трогать**: никаких изменений размеров/позиций в `Slide.vue`,
   `SlidePresentation`, компонентах без отдельной задачи (иначе поплывёт mp4).
5. **Верификация после каждой правки**: `grep`/`ls` сразу (урок клоббера P2.1), рестарт бэкенда
   после правок бэкенда (нет `--reload`!), батарея: эндпоинты + трансформы 200 + ноль ошибок
   в логах + `git diff` review в конце фазы.
6. **Мусор за собой**: тестовые слайды/пресеты/токены удалять в той же задаче; p4/p13 — эталонные,
   их трогаем только чтением (кроме явных тестов с restore).
7. **Доки в той же фазе**: `AGENTS.md` (контракты), `DATABASE.md` (таблицы/эндпоинты),
   план-док (итерация DONE + приёмка).
