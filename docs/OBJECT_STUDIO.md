# OBJECT_STUDIO — создание объектов прямо в редакторе

Цель: в чате сказать «сделай старый фонарь с тёплым светом» или загрузить фото —
и получить объект в библиотеке, готовый к вставке в сцену.

**Прототип (2026-10-25):** `core/public/object-studio.html` — загрузка GLB
(URL или файл), факты (меши, вершины, треугольники, материалы, габариты),
pivot/ground/facing, сокеты, черновик `sceneasset/1`, проверка GLB.

Сохранение и редактирование:
- список сохранённых объектов из `GET /api/scene-assets`;
- `Новый` / `Сохранить` / `Удалить`;
- локальный GLB загружается в `/uploads/scene-assets` (`POST /scene-assets/upload`);
- манифест сохраняется в таблицу `scene_assets` (`POST/PUT /scene-assets`);
- клик по объекту в библиотеке открывает его и заполняет форму.

Формат — `docs/ASSET_FORMAT.md`. API — `docs/API.md` §7.6.


---

## 1. Два входа

### A. Текст/чат
```
«Сделай деревянный указатель с надписью "Лес"»
«Нужен старый фонарь, тёплый свет, чугун»
«Сделай 3 варианта машины: красная, синяя, жёлтая»
```

### B. Фото/референс
- загрузить изображение;
- выбрать режим:
  - **sprite/cutout** — вырезать объект, использовать как картинку;
  - **stylize/vector** — стилизовать в SVG/HTML (приближение, не 1:1);
  - **reference** — использовать как референс для нового объекта.

**Ограничение:** фото не даёт готовый риг. Это либо спрайт, либо стилизация.
Риг (кости/виземы) — отдельный этап (Rive/DragonBones/SVG).

---

## 2. Пайплайн

```
prompt/photo
  → AI Object Author
  → HTML/CSS/JS + props_schema + metadata
  → sandbox preview
  → validation (forbidden APIs, determinism, overflow)
  → human approve
  → save to library (objects)
  → insert into scene
```

Metadata:
```json
{
  "slug": "old-lantern",
  "title": "Старый фонарь",
  "category": "prop",
  "domain": ["outdoor"],
  "environments": ["forest", "city"],
  "surface": "ground",
  "views": ["front", "side"],
  "default_view": "front",
  "mechanics": ["flicker"],
  "tags": ["light", "vintage"]
}
```

---

## 3. UI

В редакторе, вкладка Objects:
- кнопка **+ Создать объект**;
- поле промпта / загрузка фото;
- превью;
- поля metadata (domain, surface, environments, views);
- кнопки **Проверить**, **Сохранить в библиотеку**, **Вставить в сцену**.

В библиотеке:
- карточка объекта;
- превью/thumbnail;
- теги/совместимость;
- «дублировать/вариант».

---

## 4. API (план)

```http
POST /scene-library/objects/generate
{
  "prompt": "старый чугунный фонарь, тёплый свет",
  "reference_image": "/media/...",
  "category": "prop"
}
→ { "code": {...}, "props_schema": {...}, "metadata": {...}, "preview": "..." }

POST /scene-library/objects
{
  "slug": "old-lantern",
  "title": "...",
  "code": {...},
  "props_schema": {...},
  "metadata": {...}
}

POST /assets/upload
```

Пока `generate` — план; после подключения LLM-агента по API.

---

## 5. Валидация

- Нет `rAF`, `Date.now`, `setInterval`, `Math.random` без seed.
- Нет внешних `fetch`.
- Нет бесконечных CSS/SVG-анимаций.
- Контент не выходит за кадр.
- Детерминизм: два `seek` → одинаковый кадр.
- Совместимость с мирами.
- Размер/сложность в бюджете.

---

## 6. Фото: что реально можно

| Режим | Результат | Ограничение |
|---|---|---|
| Sprite | PNG/WebP с прозрачностью | не анимируется по частям |
| Cutout | вырезанный объект | зависит от качества фона |
| Vectorize | SVG-приближение | не идеально, нужна чистка |
| Reference | новый объект по мотивам | не копия 1:1 |

Для персонажей фото → риг **не делаем**; это отдельный тяжёлый пайплайн.

---

## 7. Фазы

1. Ручное создание объекта через JSON/код (уже есть).
2. Кнопка «Создать объект» + промпт + сохранение в библиотеку.
3. Фото → sprite/cutout.
4. AI-генерация кода + preview + approve.
5. Варианты и авто-теги.
6. Риги/персонажи — отдельно.
